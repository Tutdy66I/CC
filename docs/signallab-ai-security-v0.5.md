## 建议方案（待确认，未启用）

1. **单人本机模式**：明确只绑定 loopback；远程访问由显式开关控制。当前生产监听行为保持原样，避免破坏已有访问方式。
2. **多人部署模式**：优先复用部署平台的 OIDC/访问网关；后端验证已签名身份，清除外部伪造身份头。需要同源安全会话、HttpOnly/Secure/SameSite cookie 及适当 CSRF 防护；不要把静态共享 secret 放进前端。保留无账号的本地实验功能。
3. **共享限流**：经确认的受信代理链解析地址；按用户和 IP 分层限流，Redis 等共享后端原子控制并发/速率，实例重启不重置预算。存储失败时对收费模型调用 fail closed，同时保持本地仿真可用。
4. **用量预算**：由用户确认每用户每日 token/金额及全局月度上限。调用前按模型 tokenizer/已确认价格预留输入和最大输出额度，完成后按上游 usage 对账；未知 usage 保守保留预留额，取消也不能直接退回全部额度。原子预留防止并发越额，供应商平台另设硬预算和告警。
5. **低侵入加固**：有界上游响应、固定错误码、仅记录 request-id/状态/耗时/token，不记录密钥、问题和快照正文。上线前做真实代理、认证失效、限流窗口切换、多实例和预算竞争测试。

这两种运行模式以及登录方式、代理拓扑、预算数值需要部署方确定后再实施；本轮仅完成方案与现有防护回归测试。
费用阈值不能凭空设定，也不能声称仅凭 max_tokens 就有总费用上限。

## 本轮证据

- 单元测试覆盖配置缺失、输入限制、固定教学上下文、上游错误隐藏与预取消。
- 新增真实本地 HTTP 测试覆盖 UTF-8 超大请求 413、慢请求 408、并发 429、断连取消上游、按直接地址计数以及伪造转发地址不能绕过限流。
- 生产 E2E 清除 AI_API_KEY/AI_BASE_URL/AI_MODEL/DEEPSEEK_API_KEY，验证真实 503；其他助教场景只使用标明的浏览器路由替身。浏览器不允许外部网络请求。
- `git ls-files -- '*key*' '.env*' '*.local'` 未发现追踪的这些文件。此检查不是全历史密钥扫描，不能据此宣称从未泄露；本轮未读取用户本地凭据或打印进程环境。
- npm 全量审计报告 [JSON](signallab-dependency-audit.json)：7 项告警（6 high、1 moderate），涉及 Vite/PostCSS 等开发工具链；`npm audit --omit=dev` 为 0。未执行自动依赖升级，仍需安排工具链补丁和完整回归，开发服务器不应无访问控制地暴露。

资源、超时和第三方费用限制参考 [OWASP API4](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/)。
