# SignalLab AI v0.5 工程化计划

日期：2026-10-21。基线：`ae8d047`，Node 24.16.0，59 项单元/HTTP 测试通过。

## 审查与范围

- `signallab.ts`：单位能量 BPSK，Mulberry32，Box–Muller 每采样消费两个随机数；判决 `r >= 0` 为 0。
- `qpsk.ts`：I/Q 分别承载一个 BPSK 比特，Eb=1、Es=2；不改变映射或噪声路径。
- `berSweep.ts`：每点交替 01，比特上限 1,000,000；理论值、Wilson 区间和零误码单侧上限均保持不变。
- Worker 扫描八点，种子 `(base + index) >>> 0`；取消通过 terminate，保持协议和 UI 功能。
- 助教有基础 HTTP 防护，无身份认证、用户预算和持久限流。先审查、测试并提出方案，不强制启用新认证策略。
- 当前无 Actions 工作流；浏览器检查记录存在，但没有可复跑的 E2E 套件。

## 选择与取舍

采用流式 BER 误码计数：只在扫描路径省去四个 O(N) 数组，与完整 BPSK 仿真逐点精确比较。
备选 typed arrays 仍有 O(N) 内存；分块仿真若每块重置 RNG 会改变种子语义，均不采用。
抽取同一个 AWGN 采样器，保持 PRNG、浮点计算表达式、调用顺序、每位噪声消费量；保留完整仿真供波形、QPSK 和基准参考。

## 实施顺序与验收

1. **基准先行**：独立子进程、显式 GC、预热、五次完整八点扫描；10k/100k/1m 三档。记录中位数、最小/最大耗时、heapUsed 增量、进程峰值 RSS 和环境元数据。先保存未优化基线。
2. **测试和优化**：冻结随机采样数值，覆盖扫描范围、种子 0/最大值、奇偶/最小/最大样本；优化后完整结果（含统计区间）与原数组参考路径一致。基准只作信息输出，CI 不使用机器相关的时间阈值。
3. **CI / E2E**：Node 24、npm ci；测试、Lint、独立 TypeScript 检查、生产构建；生产服务器上的桌面及移动 Chromium。验证参数错误、无噪声恢复、真实 Worker 扫描及种子回绕、取消、报告下载、助教快照/失败/取消。外部模型不计费，浏览器使用明确的本地替身。
4. **助教审查**：增加真实 HTTP 限流/大小/取消测试，记录认证、代理、超时、成本预算和密钥的现状及分阶段建议；不读取本地密钥，不修改部署或认证行为。
5. **交付**：README、开发指南、基准结果和逐文件验证报告；每个有意义阶段格式化、验证并提交。保留用户已有工作区改动，不部署。

## 风险与边界

Node 基准不代表所有浏览器；RSS 为进程级峰值，heapUsed 采样不等同精确分配总量。
端到端以 Chromium 桌面/移动为首轮覆盖，移动为模拟设备。真实供应商费用、响应质量和身份服务尚不验证。
CI 工作流可在本地检查其等价命令，GitHub 远端执行需推送后确认。
