# SignalLab v1.4 同步研究工具：工程准备

本目录的工具用于工程预检和未来的独立研究；**当前尚未批准正式研究**。不要创建正式授权文件、运行正式 101,504 帧、上传原始数据或改变 v1.3 封存。本说明不构成研究结果。

冻结清单由 `scripts/v14-study-common.mjs` 生成并以 SHA-256 `838c09680a471a05c96b79fee70fe3cdb447f9af1894e4c698b069234449c6b6` 固定：四个场景为 AWGN/固定三径 × 0/8 dB，CFO 0.25、STO 8、CP 16、QPSK、data Eb/N0；每场景 25,376 帧，批次 0–24 各 1,000 帧，批次 25 为 376 帧。种子为 `3140000000 + batch`，四场景的相同批次共享种子和局部帧号。每个有界帧内的估计减未同步 BER 差采用完整分母；擦除扩展该差的上下界。四项比较使用 95% 同时置信度的 Hoeffding–Bonferroni 界，固定样本完成前不计算正式区间。

运行器以 20 帧为提交块，保存原始帧对象及 SHA-256 链，不使用最终汇总来恢复。数值模块从已校验的内存快照加载，续跑拒绝不同的源码、工具和运行时指纹。已提交目录经独占发布锁原子重命名；完整但尚未发布的暂存块会在校验后复用。损坏、重复或含多个不明确暂存块的目录会保留并停止。独立 Python 审计器逐块读取并核算计数、BER 和配对差；正式固定样本完整时可计算候选同时区间，候选区间不代表已批准的正式结论。

Windows 上目录重命名若返回 `EPERM`，运行器会在持有发布锁时记录该错误并在 100 毫秒后重试，最多执行五次；每次重试前检查目标不存在，暂存目录消失、目标出现或错误持续时保留证据并停止。其他系统和错误不重试。`publication-retries.jsonl` 记录每次错误，独立审计检查记录格式并报告数量；该日志不在批次哈希链内，不能作为防篡改证明。修改工具后旧研究快照不能续跑，禁止为绕过身份检查修改原有证据。

Windows 宿主使用既有原生作业对象强制数值进程 512 MiB 上限，独立计时器对每个会话预支 60 秒；租约带哈希链与副本，累计不超过 3,600 秒。正式模式在计算 45 秒后于提交块边界暂停并需显式恢复，不能跳过或缩减样本；独立看门狗在预留时限内终止卡住的进程及宿主。若强制终止使资源回执缺失，独立审计不会输出候选正式区间。累计预算保守计入整笔预支。每次启动及每块写入前核查至少 8 GiB 可用空间；数据分配和 32 MiB 附加预留共同受 4 GiB 约束。正式执行需要单独授权文件，绑定协议、源码快照、目录和样本量；本阶段不会创建授权文件。

工程预检可在 Windows 从 `react-app` 运行 `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File scripts/v14-study-preflight.ps1 -SeedOffset 0`，再以 1、2 运行两次。预检每次固定 100 帧，使用同一分块、原生宿主、存储和独立审计路径；结果只用于工程评价。审计命令为 `python -I -B scripts/v14-study-audit.py <预检目录>`。`npm run test:v14-study` 执行小规模合成故障和审计测试，不执行正式研究。

预检及正式输出分别存入项目 `output/signallab-v14-study-preflight/` 和 `output/signallab-v14-study-formal/`，均由 `.gitignore` 排除。失败会话、损坏文件和未决暂存目录需要保留，不得为获得通过而删除。

另一次 100 帧工程故障预检在第 1、3 个提交块后分别终止进程，第三个原生会话恢复并完成；独立审计核对了全部 100 帧、三个会话回执和累计 180 秒预留，最终数据链与相同种子的不中断预检一致。两次故障记录均保留在本地。该测试不涉及正式授权或正式样本。

限制：正式授权路径、完整 5,076 个块的真实生产运行、正式规模的多会话恢复以及完整正式审计尚无全规模实测。原始帧记录保存每分支误码数和擦除数，不保存逐位发送与接收判决或连续波形；独立审计可重算比率和区间，但不能从逐位判决重新验证误码计数。哈希链不提供独立异盘备份，也不能独立证明所有外部删除或回滚；文件同步和目录重命名的断电持久性依赖 Windows 文件系统。三次短预检不能证明完整样本的时间或存储预测，正式研究仍须单独审阅和批准。v1.3 原始数据的独立异盘备份仍未完成。
