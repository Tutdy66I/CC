# Public multistage DSP certification probe

This is exploratory infrastructure, not a protocol, a complete receiver proof, or research data. It uses three fixed public inputs, without random roots or seeds. The instrumented copy is made in memory from compiled production code and checks its FIR, FFT, LS and ZF outputs against the uninstrumented functions bit for bit. This output parity does not prove that every internal node of the uninstrumented function took the same optimization path.

| Case                | Complex FIR taps | FFT | FIR / FFT / LS / ZF recorded primitive operations | QPSK axes             |
| ------------------- | ---------------: | --: | ------------------------------------------------- | --------------------- |
| `fir2-fft8`         |                2 |   8 | 128 / 162 / 15 / 15                               | certified / certified |
| `fir3-fft16`        |                3 |  16 | 384 / 418 / 15 / 15                               | certified / certified |
| `fir4-rounded-fft8` |                4 |   8 | 256 / 162 / 15 / 15                               | certified / certified |

The dyadic-tap cases have point intervals at all FIR nodes; they do not demonstrate general FIR error growth. The four-tap case uses non-dyadic taps: 123 of 256 FIR operation intervals and 134 of 162 FFT operation intervals have unequal bounds. These counts are not themselves ULP widths or evidence of unbounded growth.

The FFT input is the first N complex FIR outputs; the first FFT bin is divided by a fixed complex unit pilot to obtain one LS value, and the second is divided by it by the production scaled ZF method. This is not an OFDM training sequence, capture or complete multi-carrier receiver. FIR input accumulation, bit reversal, butterfly order, normalization and scaled division follow the current compiled source. The audit independently propagates rational interval endpoints, outward to binary64 at each arithmetic operation. Angle inputs are checked bit for bit; sin/cos and sqrt use the existing mathematical bounds and must satisfy the existing adjacent-float certification. The propagation is conservative, not a claim that all values inside each interval are attainable. The output JSON contains every operation's observed operands, bounds and result bits. Numeric intervals identify +0 and -0, so intermediate signed-zero bit equivalence is not certified; the instrumented and uninstrumented stage outputs are compared with `Object.is`.

These cases have no boundary-uncertified axis. The existing separately tested `zf-boundary` remains boundary-uncertified on its first axis. No conclusion about that input can be inferred from the three new cases. A node outside its envelope, wrong decision, changed fixture, missing or reordered node fails the audit. A zero-crossing denominator or an uncertified transcendental stops it rather than relaxing the rule; partial trace and offending input are saved in stderr when available. The negative tests exercise missing nodes, changed output, out-of-bound operands and wrong decision.

The independent evidence runner stores raw producer and audit stdout, stderr, exit codes, runtime executable identities and hashes, source hashes, complete traces, summary and a SHA-256 file manifest. CI uploads these public files for 14 days even on failure where generated. CI artifacts are temporary, not independent long-term backups. Time and Python `tracemalloc` are single-run diagnostic measurements; they do not measure Node/Worker peak memory and are not an execution budget. No complete capture, LS training sequence, 128-point FFT, noisy channel, signed-zero intermediate proof, directed libm implementation, cross-runtime proof or full runtime dependency closure is included. The small samples are insufficient to justify a 128-point certification claim; further cases, accuracy and resource scaling must be studied before expansion.
