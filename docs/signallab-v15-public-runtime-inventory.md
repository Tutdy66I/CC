# Public numerical audit runtime inventory candidate

This inventory is based on PRs #25–#29 and public fixed inputs only. Its overall status is **unresolved**. It is not `06-dependencies`, a complete runtime closure, a formal protocol, or an attestation against a malicious coordinated code and fixture change.

The four round-two Python audits use `importlib` to load the rational reference and invoke the corresponding Node public entry; the ZF audit additionally loads the interval reference and invokes an instrumentation entry, which invokes the interval entry and dynamically imports a generated `data:` module. The 37-input numeric audit invokes its own Node entry. Static Python imports and literal file references are captured with `ast`; static Node ESM edges are parsed with the installed TypeScript parser. The fixture pins the declared scoped inputs and expected graph with LF-normalized SHA-256, not an immutable archive identity. Raw file hashes are recorded separately. A pinned file, graph, fixture, fixed identity or required evidence mismatch fails the check.

The interval entry imports compiled FIR, FFT, equalizer and OFDM modulation; the modulation module in turn imports BPSK, QPSK and QAM16 modules. All seven compiled modules are rebuilt in a temporary directory using the installed compiler and compared byte for byte with the actual `.test-build` files. Their raw hashes are compared to the existing round-two evidence snapshot. This detects a mismatch, but two builds with the same compromised compiler may agree. The fixture and code are reviewable repository material, not independently authenticated roots.

The inventory validates the existing 37-result numeric evidence and round-two artifact manifest, compares Python and Node/V8 executable identities with those reported by both audits, and records the workflow hash. It compares installed versions and package metadata hashes for lock-listed packages; platform-optional omissions are listed. It does **not** verify npm tarball integrity against installed files, find extraneous packages, or prove that all installed packages were used. Action tags, hosted runner image, TypeScript dependencies, system libraries, Python standard library/native modules, Node/V8 internals, hardware, floating-point environment, `Math` implementation and operating system loader remain unpinned or incompletely identified.

`data:` code, computed imports, subprocesses, builtins, Python `importlib`, native libraries and a concurrent file replacement are outside the guarantees of static parsing. Literal references are an overapproximation and are not a runtime trace; matching them to the public evidence does not establish what every subprocess loaded. The executable hashes identify individual observed files, not their complete dependency chain. Unknown dependency categories remain visible in the result; do not infer equivalence merely from matching package versions or numerical output.

CI saves raw inventory JSON, stderr, subprocess exit codes, static graph, compiler output, deterministic identity subset and SHA-256 manifest in `public-runtime-inventory` for 14 days. Failed checks retain whatever evidence was generated. Timing and memory are not part of the deterministic comparison. This temporary artifact is not an independent long-term backup. A later closure design needs authoritative environment and toolchain pinning, verified dynamic/native load capture, race-resistant snapshots, independent replay and backup/recovery exercises before `06-dependencies` can be considered for freeze.
