# SignalLab AI v1.5 第二轮公开数值认证：候选结果

状态：工程性公开固定向量；不是完整 04-numeric 认证、协议冻结或研究结果。基线 `e83681a94127e71f9e3146a47d4a1cafbb680da7`。未使用研究随机根或研究帧。所有方法和边界均需独立数学及代码审查。

## A：公开超越函数包络

`v15-envelopes-public-audit.py` 用精确有理数实现正数 log 的参数约化：`x=m·2^k`、`1≤m<2`，对 `t=(m−1)/(m+1)` 的非负级数求下界，以上界替代首个遗漏项以后全部分母得到尾项上界。`log 2` 同样使用 `t=1/3`；负 k 时调换上下界。hypot 在有理数上精确构造 `x²+y²`，用整数平方根给出上下界。只对有限合法输入使用；非有限、域外和溢出行为未完成认证。

`v15-angle-public-audit.py` 用 Machin 恒等式与有理交错级数包络 π 和 atan；sin/cos 通过 π 区间作象限约化，再对 `[-1,1]` 使用交错级数。对约化结果采用向外 dyadic 截取，降低有理分母增长；若无法证明同一个象限，返回 `uncertified`。平方根、有理转 binary64 与相邻浮点判定仍依赖第一轮工具及其 CPython 舍入假设；带符号零的适用分支另行检查。零零 atan2、非有限输入及更广泛输入没有建立完整契约。

在 Node 24.16.0/V8 13.6.233.17-node.49、CPython 3.9.12、Windows x64 的单次固定输入运行中：log 6/6、hypot 6/6、atan2 10/10、sin 8/9、cos 8/9 通过。sin/cos 各有一个 `Number.MAX_VALUE` 输入因 π 约化区间不足被标为未认证；不是 Node 输出反例。观察到的失败为 0，不能推出全 binary64 范围可行或所有函数正确舍入。`v15-round2-public-selftest.py` 的六项自测覆盖界嵌套、整数平方根、特殊值停止及简单恒等式；并非完整独立形式证明。

另用 mpmath 1.2.1、100 位十进制精度作非证明性 sanity check：26 个通过的角度向量中排除 4 个负零输入，其余 22 项落在对应界内。首次直接比较 `atan2(-0,-1)` 时发现 mpmath 输入转换丢失负零，把其当成正零象限；该现象是参考工具限制而非生产数值反例。负零相关项按前述位级和象限规则单独检查。

## B：最小真实计算图

`v15-interval-public-node.mjs` 使用 TypeScript 编译后的既有 `convolve`、`fft`、`equalizeOfdm` 和 `ofdmDecode`，输入为 4 个固定公开案例。Python 有理区间工具按源码顺序传播 47 个运算节点：单位单抽头 FIR、2 点 FFT 蝶形与 `1/sqrt(2)` 缩放、固定非零 CSI 的缩放复除和 QPSK 符号判决。每个节点计算实数区间并向外包到 binary64，禁止分母区间跨零；对节点的区间记录逐项保留，但 Node 实测对照点只有 FIR 输出、FFT 输出、sqrt/scale、最终均衡坐标与判决，并未逐节点探针生产代码。区间忽略中间 `+0/-0` 位区别，不能认证有符号零字节。

四个案例的上述生产对照点均未落在区间外；ordinary、cancel、near 两轴均可认证，`zf-boundary` 的一轴跨零为 `boundary-uncertified`、另一轴可认证。此案例没有出现实际不一致；它展示的是保守传播不能确定一轴，而不是算法失败或全尺寸 FFT 的统计结论。刻意篡改输出和判决的自测被识别为不一致。

## C：分支语义与资源

当前独立分类函数对严格 `>1e-24`、`>=0.1`、零判决和精确峰值并列进行合成区间单元自测：完全处于一侧可分类，跨界/重叠则未认证，精确单点并列保留较早峰。它们尚未与真实捕获路径的全部中间量形成端到端认证；不能把合成区间等同于真实接收判决测试。

最终三份本地 JSON 的单次 wall-clock 分别约 0.58 s（log/hypot）、0.45 s（角度）、0.07 s（小图）；Python tracemalloc 峰值约 96 KB、98 KB、130 KB，包含 Python 子流程等待但不含 Node 进程和原生库峰值。这些不是性能分布、真实 RSS 峰值或研究执行器预算。初版对未截断的有理约化进行试算时未及时结束并被中断；该尝试没有完整计时结果。后续使用向外 dyadic 界，不得把这次观察解释成普遍上界。
