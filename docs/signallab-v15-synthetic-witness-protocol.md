# SignalLab AI v1.5 方案 A 公开合成实验协议候选

本协议供独立审查。基线为 `c233e349a23c473bb775750d6a9c17ebe8d700ac`。输入限于 PR #33 的固定公开合成 ZIP、manifest、anchor 及专门制作的合成负例。实验检验授权签名、独立检查点、防回滚及模拟撤销；实施须单独批准。PR #34 给出了方案 A 的信任模型，PR #33 的独立验证器提供原始对象的完整性检查。[保管设计](signallab-v15-evidence-custody-design.md) · [固定合成对象及独立复核](signallab-v15-synthetic-independent-replay.md)

## 字节规范

- 声明、签名封套、授权表、检查点、撤销表及信任配置均使用严格 UTF-8 和 RFC 8785 JCS。接收端在对象构造前检查各层重复键（按解码后键名），拒绝 BOM、非法 UTF-8、未配对代理项、Unicode 非字符和非法 JSON。校验 schema 后比较接收字节与 JCS 输出，拒绝非规范表示、空白和尾随换行。输入经规范化后仍不符合原始字节要求时直接拒绝。
- 此候选在 I-JSON 基础上仅允许表中所列 ASCII 键及受限 ASCII 字符串，无自由文本，拒绝未知键、缺键及类型转换。整数词法限 `0|[1-9][0-9]*`，解析前按十进制检查在 `0..9007199254740991` 内。序号及代数从 1 开始。拒绝小数、指数、负零和非有限值。摘要及密钥 ID 为 64 字符小写十六进制，Ed25519 公钥为原始 32 字节的小写十六进制，签名为原始 64 字节的小写十六进制。SHA-256 指摘要的 32 字节及其固定十六进制表示。
- 每份协议 JSON 上限 64 KiB，本实验每个原始证据对象上限 16 MiB，证据文件只取下表三个固定名称。原始 ZIP、manifest、anchor 按读到的原始字节计算长度和 SHA-256，保留原件及顺序。PR #33 的对象格式继续由其独立只读校验入口检查，包括 anchor 的内部引用及 ZIP 成员。JCS 只用于本候选新增的协议对象。
- Ed25519 使用 RFC 8032 的纯 Ed25519 模式，采用经独立审查的维护中实现。先检查固定编码长度和密钥角色，再验签。禁止算法协商、自动降级及把输入指定的库或公钥当成配置。[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html) · [RFC 7493](https://www.rfc-editor.org/rfc/rfc7493.html) · [RFC 8032](https://www.rfc-editor.org/rfc/rfc8032.html)

### 声明及签名

下表列出 `declaration` 对象的全部字段。固定枚举大小写敏感。下文的 `declarationSha256` 指声明的 JCS 原始字节摘要。

| 字段                                        | 类型与约束                                                                                                                                   |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`, `kind`                           | 整数 `1`，字符串 `declaration`                                                                                                               |
| `scope`, `stream`                           | 字符串 `synthetic-only`、`signallab-v15-witness-a`，所有协议对象和信任配置绑定同一 stream                                                    |
| `archiveId`                                 | 字符串 `fixture-1`，在整个合成发布序列内固定                                                                                                 |
| `sequence`, `previousDeclarationSha256`     | 正整数。序号 1 的前序值为 JSON null。后续值为紧邻前一序号的声明摘要                                                                          |
| `objects`                                   | 对象，字段恰为 `synthetic.zip`、`synthetic.manifest.json`、`synthetic.anchor.json`。每项为恰含 `byteLength` 和 `sha256` 的对象，长度为正整数 |
| `sourceCommit`, `dependencyInventorySha256` | 40 字符小写 Git 提交十六进制及公开依赖清单原始字节摘要。与预登记夹具匹配，清单覆盖范围继承其 `unresolved` 状态                               |
| `rosterSha256`, `policyId`                  | 对应授权表的原始 JCS 摘要，及固定字符串 `synthetic-preregistered-v1`                                                                         |
| `signers`                                   | 恰含 `P`、`R` 的对象，各值为预授权的不同密钥 ID                                                                                              |

独立签名封套有且仅有 `version: 1`、`kind: "signature"`、`algorithm: "Ed25519"`、`role`、`keyId`、`targetSha256`、`signature`。P、R 的 `targetSha256` 为声明摘要，密钥 ID 须分别与声明和授权表相符。W 的封套只能签检查点，`targetSha256` 为该检查点的 JCS 摘要。密钥 ID 为原始公钥字节 SHA-256。声明要求恰好各一份 P/R 封套，检查点要求恰好一份 W 封套。重复角色或额外封套拒绝。候选签名消息如下，分隔字节恰为一个 NUL，尾部无附加字节。摘要和签名均位于所引用对象外，避免自引用。

```text
P   ASCII("signallab/v1/synthetic/declaration/P") || 0x00 || JCS(declaration)
R   ASCII("signallab/v1/synthetic/declaration/R") || 0x00 || JCS(declaration)
W   ASCII("signallab/v1/synthetic/checkpoint/W")  || 0x00 || JCS(checkpoint)
```

### 授权、见证与撤销

以下每行列出该对象的全部字段，除表列值外，每个对象均有 `version: 1` 和前述固定 `stream`。

| 对象           | 其余字段与约束                                                                                                                                                                                                                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 授权表         | `kind: "roster"`、`policyId: "synthetic-preregistered-v1"`、`keys`。键集恰为 P、R、W，每项含 `keyId`、`publicKey`、`firstSequence`、`lastSequence`，包括两端的授权序号范围，三把公钥及 ID 均互异                                                                                                                              |
| 检查点         | `kind: "checkpoint"`、`sequence`、`declarationSha256`、`previousCheckpointSha256`、`rosterSha256`。序号与声明相同，首项前序为 null，后续必须引用紧邻前项的检查点 JCS 摘要。所有检查点只能由授权表的 W 签署                                                                                                                    |
| 撤销表         | `kind: "revocations"`、`epoch`、`rosterSha256`、`entries`。条目按 `keyId` 字节升序且唯一，字段恰为 `keyId`、`reason`（`retired` 或 `compromised`）、`firstDisallowedSequence`、`lastTrustedCheckpointSha256`（摘要或 null）。必须引用已知密钥。非空截止证明须指向撤销前已由独立渠道固定的检查点，且其序号恰比首个禁止序号少 1 |
| 验证器信任配置 | `kind: "trust"`、`rosterSha256`、`revocationsSha256`、`revocationEpoch`、`expectedSequence`、`expectedCheckpointSha256`。由独立通道交付。撤销前检查点证明另由接收方的既有可信收据提供，不能由撤销表自行建立                                                                                                                   |

同一实验使用固定授权表。模拟失效通过角色的授权序号区间和撤销表表达。撤销表与信任配置分别保存，前者由后者固定原始字节摘要和代数，不接受从归档更新撤销状态。独立更换信任配置需新收据及单调代数，旧快照可用于历史审计，不能当作当前授权策略。真实轮换、授权根恢复及签发时间证明留待另行设计。

## 角色与验证次序

| 角色       | 权限和证据                                                                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| P · 发布者 | 构造合成对象，登记原始长度、摘要与声明前序，签署 P 前缀。无权签 R 或 W，也无权更新接收方信任配置                                              |
| R · 审查者 | 独立重算对象、检查公开来源和预期前序，核对声明后签署 R 前缀。保留其审查输入及复核输出。无权代替 P 批准或颁发最新检查点                        |
| W · 见证者 | 预先持有授权根、策略和上一个已知检查点。验证 P/R 后才见证严格递增序号。保留检查点链并独立供复核方确认，无权替 P 或 R 签署或静默改写既有检查点 |

复核方先从独立审查交付获得授权表、撤销表、当前检查点及其前序记录，核对确认后登记信任配置的原始字节摘要，最后才接收证据包。实验收据记录用例、独立输入来源、配置摘要、检查点序号和摘要、交付先后以及操作者或夹具身份。夹具将信任输入与候选对象放在分别提供的只读目录，验证器需要显式指定预先固定的信任配置摘要。候选提供的公钥、摘要、撤销表及检查点均不能覆盖该配置。单一自动化进程执行以上逻辑角色，只能证明信任输入隔离与验签规则，不能证明人员、设备或管理权限独立。

1. 先核可信配置摘要、授权表、撤销表及独立收据。缺失信任材料、撤销代数不可确认、信任记录与已登记收据相冲突时，以未验证状态停止。明确错误的候选对象或签名直接拒绝。
2. 对当前或历史路径验证完整声明和检查点前序链，从序号 1 连续到该次复核预置的检查点。逐一验证声明摘要、P/R 签名、W 签名、固定授权范围及对应序号。待验版本额外核对所提交的原始对象，并用已通过签名和见证验证的声明中所绑定的 anchor 摘要作为 PR #33 只读验证器的预期值。前序节点只使用其已签署声明及见证材料，历史对象原始字节要单独提供才可核验。
3. 已撤销密钥在首个禁止序号及其后签署的任何角色行为均拒绝，W 也适用。对更早序号，只有其声明所属链能证明已经在独立固定的撤销前检查点内，才允许评估其历史有效性。缺少可信截止证明或无法证明在该检查点所覆盖的链上，保持未验证。遗失私钥本身不使历史公钥失效。自报时间、文件日期、单方报告均不得作为截止依据。
4. 只接受与预置序号及检查点摘要完全匹配的当前版。较早但有效且可证明在同一见证链上的版本只能在显式历史模式通过。超前但未经独立确认的版本保持未验证。拥有同一 stream、相同序号、不同声明摘要且 P/R 仍获授权的两条记录构成分叉证据，即使第二条缺少 W 见证签名。验证有效签名与授权后才将其作为分叉，保留双方记录，冻结自动接受和检查点更新。检查点提供相对已知发布顺序，不证明 UTC 或全局最新，也无法发现从未收到的分叉。

## 预登记验收矩阵

固定合成对象构造序号 1、2 的两份声明及相连检查点。A–H 保持独立信任通道的根集合固定，H 使用事先登记的另一撤销代数。I 特意替换独立信任输入。下表每例均保留所述原件与公共运行记录，复核方从受控输入重新运行只读验证，并独立重算关键字节或验证签名。

| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------- |
| A · 双签       | 两版链及固定三件对象，序号 2 的 P/R/W 均有效，预置检查点一致                                                                                               | `accept-current`。任一必要检查失败时不得接受                                                                                                      | 原始三件对象及两版签名和收据。重算全部成员和检查点摘要，独立验三个角色签名         | 只覆盖该固定合成序列                         |

## 证据、判定与实施门槛

保存每例的不可变原始输入与变异说明、源声明和 JCS 字节、签名消息字节、公钥／签名向量、两套信任输入及先后收据、检查点与撤销向量、原始 stdout／stderr／退出码、判定阶段和原因、源码提交与文件 SHA-256、库及解释器版本和身份、OS 与构建身份及全量证据清单。样本签名将来只用预先公布的测试向量材料。记录公开审计的依赖身份及其已知缺口。运行耗时可单列，确定性比较只涉及事先确定的字段。

候选结果及退出码固定为 `accept-current`（0）、`reject`（1）、`unverified`（2）、`historical-verified`（3）。异常、执行中断或未采集到实际结果单独记为工具错误，不能满足任何预期负例。保留所有运行与失败原件。

- **实验通过**要求全部已登记子例得到预期结果和原因，独立实现可仅凭保留字节及预置材料重算，I 的信任边界也得到复现。签名通过只授予相应合成声明的授权和版本状态。文件恢复和科学数值复现各自需要单独验收。
- **实验失败**包括越权接受、误拒绝有效向量、回滚接受、有效分叉未识别、把撤销不明当成已验证、不同实现的确定性结果不一致，或任何其他与预登记判定矛盾的已完成结果。
- **证据不足**包括缺收据、独立验证材料缺失、工具错误、证据不可追溯或独立复核未完成。用例中按预期返回的 `unverified` 可以证明失败关闭；实验本身证据不足则不能宣布通过。

开始实施前，须独立审查 schema、待签域、退出码与判定优先级，选择并锁定受维护的标准实现，明确独立复核入口和信任材料交付方式，并在任何执行前登记精确夹具、子例、预期状态和拒绝理由。若需修改判据，应建立新审查版本，保留先前实验及原始输出。**建议有条件 Go，仅针对完成上述审查并另行获批的公开合成实验。** 对真实证据认证、独立备份恢复、依赖闭包及正式冻结，建议维持 No-Go。本候选只交付协议设计，实验状态为未执行。
