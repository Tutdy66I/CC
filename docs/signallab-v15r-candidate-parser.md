# Candidate schema/parser infrastructure

This is an independently reviewable candidate, not a complete six-file protocol parser, research authorization, or frozen protocol. No API accepts a six-file collection as valid: `inspectCandidateJson` examines one document at a time and only recognizes known candidate fields of 01/02/03, always reporting `frozen: false`. It rejects 04/05/06 unconditionally after checking their outer field names. There is no function that produces a formal protocol identity or authorizes research.

`parseCanonicalJson` checks restricted ASCII UTF-8 bytes, one final LF, exact sorted-key spelling at every level, restricted strings and safe decimal integers. It reconstructs canonical text before comparison to catch repeated keys, alternate encodings, whitespace and negative zero; it does not by itself validate a six-file schema. Known 01 scenarios are matched byte-for-byte against the four candidate encodings, including binary64 patterns. The public-only identity test uses synthetic fixture bytes and does not call `publicTestIdentity` as a protocol parser; its Node/Python check proves only the tested packaging and mutations.

`validateDependencyGraph` validates declared, sorted paths and edges; it does not discover imports or establish closure. `verifyCandidateDependencyFiles` rejects symbolic links encountered below its chosen root and verifies bytes at the time of reading. It is not an atomic snapshot, is vulnerable to concurrent filesystem changes between checks, does not establish final runtime closure, and does not prevent hard-link mutation. Use only on an independently secured immutable snapshot; no production or security guarantee follows from these checks. The final closure must include the actual engine, parser, registry, auditor, build and runtime and be separately audited.

Blocking decisions include: the numeric proof implementation and coverage, locked runtime/OS and reproducibility scope, evidence/checkpoint byte layouts and failure semantics, approved registry binding, and complete dependency graph and safe snapshot procedure. No placeholders in 04/05/06 are accepted as an approved rule. Full PR1, frozen protocol, independent recovery and formal research remain unvalidated.
