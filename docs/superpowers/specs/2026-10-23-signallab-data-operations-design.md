# SignalLab 数据运维设计（已批准）

范围：补齐个人试用阶段的数据库配额、保留策略、应用数据备份及恢复验证。
保持现有 GitHub OAuth、RLS、游客模式、Workers 和 Node AI；公众注册关闭，Pages AI 禁用。
用户已批准本设计；配额迁移、加密备份和每日自动化可按以下范围实施。

## 方案选择

1. 推荐：数据库强制配额 + 本地加密应用快照 + 本地恢复演练。
   无需升级 Supabase 套餐；自动备份依赖本机和 Codex 连接可用。
2. 仅前端限额和手动 JSON 导出：改动少，但直接 Data API 请求可以绕过前端限额。
3. 升级托管备份套餐：运维负担较低，但引入费用，当前不执行。

## 配额

- 每个账号最多 1,000 条云端记录，包含软删除墓碑。
- 每个账号参数、结果及分析的 JSONB 文本载荷合计最多 20 MiB。
- 保留现有每条 128 KiB 载荷和分析 12,000 字符限制。
- 数据库触发器强制校验，不能仅依赖前端计数；保持现有 RLS 和列授权。
- 对同一账号的写入进行事务级串行化，避免并发绕过；失败不更新配额状态。
- 超额拒绝新增或增加载荷，仍允许读取、导出、缩短分析和软删除。
- 墓碑仍占用额度，避免删除后重新写入绕过空间限制。
- 前端明确提示达到配额，暂停自动上传重试，保留 IndexedDB 待上传记录。
- 不设置未经测量的全库字节硬上限；每账号载荷额度不等同于套餐数据库总大小。
- 上线前核对现有账号占用；当前记录保留原样，不为满足配额删除历史。

## 保留策略

- 活跃实验以服务端 created_at 计算，超过 365 天进入到期预览清单。
- 首期不自动过期、不从历史列表隐藏，也不执行物理清理。
- 墓碑无限期保留；在支持离线设备过期及全量重置协议前，不设物理删除日期。
- 本地备份暂不自动删除；超过 30 天只列出待归档文件，需另行决定清理。
- 删除 Auth 用户会级联删除云端记录，属于现有行为；本轮不删除用户。

## 备份及自动化

- 先制作一次完整应用快照，再安排每日香港时间 20:00 的本会话备份自动化。
- 使用已授权 Supabase 插件只读导出 experiment_records，所有者 ID 直接来自记录；
  不导出 Auth 表、邮箱、密码哈希、会话、JWT、OAuth secret、service_role 或模型密钥。
- 同步保存当前 Git 提交及迁移源文件，明确这是应用级备份，不是完整 Auth/整库备份。
- 备份存放于 react-app/backups.local/，确认被 Git 忽略；采用 Windows 当前用户 DPAPI 加密。
- 不将明文快照、凭据或备份放到 Git、公开 Actions artifacts 或聊天输出。
- 导出采用有界分页；对比导出前后记录数和内容摘要，变更或截断时重试/失败告警。
- 只有完整性校验通过才原子发布新备份；失败不覆盖上一份可用备份。
- 自动化成功时保持安静，只报告失败、完整性异常或需要用户处理的事项。
- 自动化需要本机、Codex 和插件连接可用，会使用 Codex 运行额度，不调用应用收费 AI。
- DPAPI 绑定当前 Windows 用户；该方案不提供电脑丢失后的异机灾难恢复。
  可移植恢复密钥及异地副本需另行选择保存方式，不能宣称已经具备。

## 恢复验证

- 解密、校验摘要、在临时 PGlite 数据库加载受版本管理的 schema 和应用记录。
- 核对记录 ID、所有者 ID、参数、结果、分析、修订号、时间戳及墓碑均一致。
- 只在临时数据库构造 Auth 用户占位行以验证应用外键；不伪称恢复真实 OAuth 身份。
- 不向生产回灌，不覆盖现有云端数据；生产恢复必须单独评审。

- 备份测试覆盖加解密、损坏、截断、源数据变化、原子发布和本地恢复比对。
